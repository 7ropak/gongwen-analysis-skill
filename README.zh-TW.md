# 公文分析（Gongwen Analysis）

[简体中文](README.md) | [English](README.en.md) | 繁體中文 ｜ v1.0.0

> **公文分析** — 一套面向企業公開文本的分析技能包。
> 給它一份公告、財報或危機聲明，它推演各方會怎麼反應；給它一個事件，它反推該怎麼說、能承諾到哪一步。

適用：Claude Code、Codex、WorkBuddy、豆包，以及其他能載入 Markdown 指令檔案的 Agent。

---

## 這個技能包做什麼

輸入一份企業公文——上市公司公告、定期報告、澄清公告、問詢回覆、危機聲明、道歉信、公關稿、內部信、ESG 報告——輸出一份分層推演：這份文本說了什麼，各方會在意什麼、底線在哪、可能怎麼反應，以及接下來該盯哪些訊號。

具體做五件事：

- **拆結構**：定文種、套骨架，找出「本來該有卻沒有」的組件——缺件本身就是訊號。
- **建底座**：把時間線、主體、既往紀錄、同業對照查清，每條事實附來源與可信度等級；查不到就寫「未查到」，不拿推測填。
- **推演人**：9 類利害關係人（公眾、監管、資本、客戶、員工、供應商與通路、媒體、社區、競爭對手），按權力／合法性／迫切性排優先順序，給出觸發條件、方向、強度、時點，並判斷會不會結盟放大。
- **標話術與數字**：逐句標註聲明用了哪種策略、前後是否自洽；財報類再疊一層科目與披露訊號，對照措辭的實務讀法。
- **給結論**：最壞結果、可核驗的承諾、觀察指標。長週期事件可以立項，按期回填事實再複檢。

反向也成立：只給一個事件、沒有公文時，走發布側，產出承諾邊界三分（可承諾／不可承諾／需上報）、口徑草案與發布前審批提示。

用法分四檔：**速讀**（一頁內說清這份公文講了什麼）、**標準分析**（完整報告 + 獨立覆核，預設）、**追蹤複檢**（與上期對比）、**口徑研判**（發布側）。

系統有 2 個 Agent 和 9 個技能協作完成這些任務；判據放在知識庫裡按需讀取，不整包塞進上下文。

## 怎麼使用

純 Markdown 與 YAML，沒有執行環境要求，也不需要安裝依賴。把整套目錄放進 Agent 能讀到的位置即可。

### 路線 A：把倉庫交給 Agent（推薦）

> `https://github.com/7ropak/gongwen-analysis-skill`

Agent 會自行解析倉庫，入口是 `agents/公文分析Agent.md`。

### 路線 B：取到本地再接上

```
git clone https://github.com/7ropak/gongwen-analysis-skill.git
```

然後把這句話交給你的 Agent：讀取 `gongwen-analysis-skill/agents/公文分析Agent.md`，按其中的入口協議執行。

呼叫時只需要說清三件事：

```
呼叫 公文分析Agent：
 公文內容：[貼上原文 / 連結 / 檔案]
 主體：某公司（可省）
 模式：標準
```

發布側換成 `事件描述：……` 與 `模式：口徑研判`。時間窗、上市地、關注群體等可選欄位見 `schemas/分析输入.schema.yaml`。

## 目錄裡有什麼

- `agents/` —— 2 個 Agent：`公文分析Agent.md` 是主入口，負責編排；`分析审计Agent.md` 在獨立上下文中做覆核。
- `skills/` —— 9 個技能，一段一件：類型與結構解析、事件背景調研、利害關係人建模、聲明語用標註、財務與合規訊號掃描、分析報告生成、追蹤立項管理、口徑研判與生成、詞庫維護。
- `schemas/` —— 5 份 YAML 契約：分析輸入、分析輸出、口徑研判、追蹤立項、經驗配置。欄位與章節順序以契約為準。
- `knowledge-base/` —— 判據庫：公文類型庫、利害關係人基線、聲明策略庫、公關危機回應流程、訊號庫、潛台詞庫，以及詞庫三卷（表態程度譜系、企業聲明用詞、模糊與限定用詞）和使用者經驗。
- `prompts/` —— 可重複使用的口徑片段與輸出模板，只放被 Agent 和技能引用的內容。
- `docs/` —— 資訊架構：目錄職責與產物存放規則。

執行時還會生成 `output/`（交付版報告）、`debug/`（過程紀錄）、`data/`（調研原始紀錄與追蹤立項），這三個目錄隨倉庫分發時不包含。

能不能改：除 `schemas/` 外基本都是純文字。改詞條、加群體、換模板、調口徑，直接編輯對應檔案；改契約則要同步改引用它的技能。

## 它怎麼運作

一份公文進來，先定文種與法定性——強制披露、自律要求、自願披露、無強制，四檔決定後面哪些方法能作主判據、哪些只能輔助；這一步判錯，後面的語用分析會整體偏。接著建事實底座：時間線、主體、既往、同業，每條帶來源。然後把人放進局內，按優先順序排序，看誰會先動、會不會結盟放大。文本層逐句標註表態與限定，財務類再疊科目與披露訊號。最後歸結到結論層：最壞結果、可核驗的承諾、該盯的時點；要長期看的轉成立項，按期回填事實再複檢。

解讀側與發布側方向相反，但共用同一套群體基線與策略編號——所以「別人會怎麼讀」和「我該怎麼寫」能對得上。

## 關鍵設計

- **雙層產物**——交付版只放結果，除錯件放判據與核對紀錄。最終讀者要的是「說了什麼、會怎樣」，方法痕跡一多，推斷就容易被當成結論；需要複查的人另有完整過程可看。
- **詞庫是判據，不是詞典**——「遺憾」和「道歉」差一檔，這一檔決定對方下一步動作。把分寸差寫成可比對的條目，分析才不靠語感。
- **契約先行**——輸入、輸出、追蹤、經驗、口徑五份 schema 定義欄位，章節順序與命名只認契約，同一類報告不會每次長得不一樣。
- **雙視角共用一套判據**——兩側方向相反，但引用同一份群體基線與聲明策略編號，寫出來的口徑才能經得起自己那套推演。
- **覆核獨立於分析**——覆核者先讀原文自行判斷，再比對結論，且不讀分析者的中間推理；共用上下文會繼承同一個誤讀。
- **機率只給檔，不給百分比**——沒有校準樣本時，精確數字只是虛假的確定感；檔位加上觀察指標，才是可驗證的。

## 邊界與不做什麼

- **不構成投資建議**：不給評級、目標價、估值，也不做交易時點判斷。
- **不構成法律意見**：涉訴涉監管的判斷只寫到「需核實項 + 核實路徑」，不做法律定性。
- 只用你提供的文本與公開資訊，不檢索非公開材料。
- 潛台詞清單與量化閾值是**經驗口徑**，不是監管規則，不能當合規依據使用。
- 沒有校準樣本時，推演結論標註為未校準，可靠性低於事實層；請結合一手材料使用。
- 發布側產物是**內部研判輔助**，不是可直接對外的成品稿；不生成虛假陳述、不規避法定披露義務、不代填內部證據。
