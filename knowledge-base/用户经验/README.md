# 用户经验区

> **用途**：存放**用户自行添加的公文理解经验**——个人从实务中积累的读法、行业惯例、主体特征。
> **本区默认静默**：用户没往里填东西，就等于**未激活**——系统不读、不提示、不把它当作缺口或待办。

---

## 一、激活与静默

| 状态 | 判据 | 系统行为 |
|---|---|---|
| **未激活**（默认） | `rules:` 为空或仅余注释 | **不读本区、不在报告中提及、不提示用户补填、不计入完整性缺口** |
| **已激活** | `rules:` 至少有一条有效条目 | 分析时读取，并按下文优先级取用 |

> 激活是**用户动作**，系统不主动推动。用户明确要求「记一条经验」时才写入。

## 二、为什么单独放这里

公文理解高度依赖个人经验。理论框架（`声明策略库`、`利益相关者基线`）提供通用判据，但「这家公司历来讲话的方式」「这个行业的惯例」「我读公告时的直觉规则」只在用户手里。本区就是把这类经验**显式化、可复用**。

## 三、读取优先级（硬规则）

> **判据的唯一事实源＝`prompts/分析口径片段.md` 片段 E**；本节仅概述，冲突时以片段 E 为准。

分析时三类知识的取用顺序：**用户经验 > 知识基线 > 模型常识／联网**；与传统知识基线冲突时**并列呈现**，不静默舍弃。

## 四、条目格式

每条经验＝一条规则，字段见 `schemas/经验配置.schema.yaml`。最小形态：

```yaml
rules:
  - id: usr-001
    scope: 文种 | 群体 | 主体 | 通用        # 适用范围
    trigger: "文本中出现……时"               # 可观测触发条件
    judgment: "我据此判断……"                 # 你的判断
    source: 个人经验 | 行业惯例 | 案例复盘
    confidence: 高 | 中 | 低
    note: 可选补充
```

## 五、维护方式

- **用户直接编辑** `公文体感.md`（推荐方式，无需经 Agent）。
- 也可口头告诉本系统「加一条经验：……」，由技能 `跟踪立项管理` 的「经验登记」动作写入。
- **不做自动清理**：经验条目只增不减；发现过时条目，改用 `confidence: 低` 或补 `note` 说明失效条件，**不删除**（保留判断沿革）。

## 六、边界

- 本区只放**判读经验**，不放事实数据（事实进 `data/`）。
- 涉及具体主体的非公开信息**不入本区**。
- 经验条目影响分析结论时，报告中必须可见其来源为「用户经验」。
