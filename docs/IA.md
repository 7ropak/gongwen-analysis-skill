# 信息架构（IA）

> 存放判据：**这份文件在运行时会不会被读取？** 会被读 → 留在项目目录内随仓库分发；只有人回看 → 放 `debug/`（不随仓库分发）

## 二、读取频次

| 频次 | 内容 | 加载时机 |
|------|------|---------|
| **每次触发** | `README.md` 头部 ＋ 主入口 Agent 的 L0／L1 | 每次触发 |
| **按需** | 主入口 Agent 全文、`schemas/`、被点名的那一个 Skill | 触发时按需 |
| **执行中** | `knowledge-base/` 各件、`docs/` 长文、`debug/` 记录 | 由 Skill 在执行中按需取 |

> **知识基线不预载**：由各 Skill 在需要时按名取用（如「利益相关者建模」只读 `利益相关者基线.md`），避免整包塞入上下文。

## 三、存放规则

| 产物 | 存放位置 | 理由 |
|------|------|------|
| 分析报告（交付版） | `output/<主体>-<文种>-<YYYYMMDD>.md`（速读加 `-速读`） | 交付物；**只放结果**。命名唯一事实源＝`schemas/分析输出.schema.yaml` |
| 调试任务汇报 | `debug/调试任务汇报-<主体>-<YYYYMMDD>.md` | 调试产物；放过程内容（判据 · 缺失 · 核对 · 复核 · 待确认） |
| 复核件 | `debug/复核-<主体>-<YYYYMMDD>.md` | 调试产物 |
| 口径研判报告 | `output/<主体>-口径研判-<YYYYMMDD>.md` | 交付物（发布侧）；契约＝`schemas/口径研判.schema.yaml` |
| 跟踪立项 | `data/tracking/<事件ID>.md` | 运行时被读（复检时读回） |
| 用户经验 | `knowledge-base/用户经验/` | 运行时被读，且由用户长期维护 |
| 调研原始记录 | `data/raw/` | 运行时被读（复检时比对），非交付面 |
| 审查报告 | 默认并入报告附录；独立成件时放 `debug/` | 只有人回看 |

## 四、产物分层（交付版 vs 调试件）

> 判据唯一事实源＝`prompts/分析口径片段.md` 片段 H。

- **交付版**（`output/`）：读者＝最终读者；只回答「这份公文说了什么 ＋ 可能产生什么影响」。
- **调试件**（`debug/`）：读者＝用户／调试方；放方法论、判据、缺失、核对、复核、待办。
- 标准分析与跟踪复检**每次同步产两份**；速读模式只产交付版。
