# 词库维护

> 定位：**旁路技能（S12）**——不属主流水线，附在每次分析收尾执行。
> 作用：从待分析公文中发现**词库未收录但值得入库**的用词，按「即时询问」或「静默记录」两种方式处理；累积到阈值后统一判断、写入词库。
> 调用方：`公文分析Agent` ｜ 判据来源：`knowledge-base/词库/README.md` §入库特征（唯一事实源，本处不复制特征表）

---

## 输入

| 字段 | 必填 | 说明 |
|---|---|---|
| 公文原文 | ✅ | 本次分析的文本（含繁体） |
| 分析日期 | ✅ | 用于候选记录与阈值计数 |
| 模式 | ❌ | `即时` ／ `静默`（默认静默） |
| 已否决记录 | 自动 | 读 `_候选.md` 的「已否决记录」，避免重复询问 |

## 输出

| 产物 | 存放位置 | 何时 |
|---|---|---|
| 即时提问 | 对话内 | 即时模式；**单次最多 3 个**，按价值排序 |
| 候选记录 | `knowledge-base/词库/_候选.md` | 静默模式；追加到「候选表」 |
| 候选审阅表 | `debug/词库候选审阅-<YYYYMMDD>.md` | 触发阈值时 |
| 词库写入 | `knowledge-base/词库/<卷>.md` | **用户确认后**才写 |

---

## 执行步骤

### 步骤1：抽词面
从原文中取**非名词性、带态度或限定色彩**的短语（2–6 字）。含表态动词、程度副词、否定式、限定语、程式化套语（如「严正声明」「无可奉告」）。
> 不做全文分词——只取「读起来有分寸感」的片段，宁少不滥。

### 步骤2：过反特征
按 README 的 X1–X3 剔除：业务名词与术语、机构/人名/地名/产品名、无态度功能的通用动词。

### 步骤3：过词库与候选池（含繁简归一）
- 与词库三卷正文比对：**已收录即跳过**。
- 与 `_候选.md` 比对：已有则只更新「上下文」不新增行。
- 与「已否决记录」比对：命中则**永不再提**。
- **繁简归一**：同一用词的繁简写法（如「譴責」与「谴责」、「聲明」与「声明」）视为同词，比对前先做繁→简归一——公文体常见港台繁体。

### 步骤4：验正特征
逐词对照 F1–F6 打勾，**命中 ≥2 条**才进入下一步。在候选记录中写明**命中了哪几条**（如「F1+F6」）。

### 步骤5：按模式处置
- **即时模式**：按「价值 × 命中数」排序，**最多提 3 个**，问法：
  > 「可能遇到新的用词：**<词>**（出自「<原句>」，命中 F1＋F6）——建议收入「<卷名>」，释义为「<一句话>」。要加吗？」
  > 用户确认 ⇒ 走步骤7 写入；否决 ⇒ 记入「已否决记录」（含理由）。
- **静默模式**：追加候选行（词 / 上下文 / 出处 / 命中特征 / 建议卷 / 状态＝未决），**不在对话中提及**（避免打断）。

### 步骤6：阈值检查（每次收尾都查）
`未决 ≥ 8 条` **或** `距上次审阅已跨 ≥ 3 次分析` **或** 用户点名 ⇒ 生成 `debug/词库候选审阅-<日期>.md`：

| 词 | 出处 | 命中特征 | 建议卷 | 建议定义（含义＋隐含） | 置信 |
|---|---|---|---|---|---|

> 生成后向用户报一句：「候选池已有 N 条新词待定，审阅表在 <路径>」。**不逐条追问**。

### 步骤7：写入词库正文（仅用户确认后）
1. 按目标卷的六字段格式补齐：用词／程度／含义／隐含／判读提示／出处。
2. **出处必填**：至少「出现于 <文本>（<日期>）」；能补公开来源更好。
3. 写入后在 `_候选.md` 把该行状态改为「已收录」，**保留原记录**（可溯源）。
4. 新旧词冲突时**并列注释**，不改写既有条目。

---

## Guardrail

- **不自动改词库正文**：静默记录只写候选池；正文改动须用户确认。用户若明确授权「自动收录」，仍须满足「有出处」与「命中 ≥2 条正特征」两项。
- **不收录专名与业务术语**（X1–X3 硬排除）。
- **不重复询问**：已否决的词不再提；候选池已有的词只更新上下文。
- **单次即时提问 ≤3 个**，防止打断分析节奏。
- **宁少不滥**：拿不准的词宁可留在候选池，不提交。
- 候选记录**不写运行期元数据**（模型名、session 等），只写文本出处与日期。
