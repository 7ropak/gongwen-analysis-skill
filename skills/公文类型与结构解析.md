# 公文类型与结构解析

> 定位：流水线 **S1**——判定「这是什么文种、结构应当长什么样、缺了什么」。
> 调用方：`公文分析Agent` ｜ 判据来源：`knowledge-base/公文类型库.md`

---

## 输入

| 字段 | 必填 | 说明 |
|---|---|---|
| 公文原文 | ✅ | 文本／URL（URL 先取正文） |
| 主体 | ❌ | 未给时从文头／落款推断 |

## 输出

> **去向**：本技能产出属**过程内容**——用于内部判断并登记进调试件，**不进交付版报告**（判据 → `prompts/分析口径片段.md` 片段 H）。交付版中若需体现其结果，改用平实语言（如「声明的主旨是事实否定与态度表达」，而非「缺六段式第④段」）。

| 字段 | 说明 |
|---|---|
| 文种 | 类型库中的具体文种（如「澄清公告」） |
| 三轴定位 | 发布主体／**法定性（四档）**／时效 |
| 发布主体 | 从文头／落款识别的发布方（供 S2 复用） |
| **事件线索** | 文中提及的事由、时间、涉及第三方（供 S2 复用，无则写「文中未明」） |
| 应有结构组件 | 按对应骨架列全 |
| 缺失组件 | 应有而未见 ⇒ **异常信号**（附可能含义） |
| 结构异常 | 组件顺序错乱、票数缺失、日期倒置、前后矛盾等 |
| 分析路径建议 | 语用标注是否可作主判据（取决于法定性档） |

---

## 执行步骤

1. **取正文**：URL 输入先抓正文（保留标题、文号、落款、日期）；截图类输入提示用户提供可检索的文本。
2. **三轴定位**（逐项给出判据，不写「感觉」）：
   - 主体：从文头／落款／署名识别；
   - 法定性：查类型库 §一，**判据＝该文种是否有强制格式规范**；
   - 时效：定期 or 触发式（看是否有明确触发事由）。
3. **套骨架**：按类型库 §三 取对应骨架（①公告通用 ②定期报告 ③危机声明六段 ④问询回复，或「其余文种结构映射」表）。
4. **逐组件勾选**：产出「应有／实有／缺失」三列。
5. **缺失组件解读**：对照类型库 §四「结构缺失＝异常信号」表给出提示，**标注为判读级**。
6. **给路径建议**：法定披露 ⇒ 以「结构完整性 ＋ 财务信号」为主轴；自愿披露 ⇒ 允许以语用标注为主判据。

---

## Guardrail

- 文种判不清时**给最接近的 2 个候选 ＋ 区别判据**，不硬判。
- 类型库未覆盖的文种 ⇒ 标注「无权威结构标准」，只做「组件观察」不做「缺失判定」。
- 缺失＝异常 的推断**属判读级**，不得写成事实指控。
- 党政机关公文与上市公司公告的规则体系不同，勿混用骨架。
