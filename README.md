# 公文分析（Gongwen Analysis）

简体中文 | [English](README.en.md) | [繁體中文](README.zh-TW.md) ｜ v1.0.0

> **公文分析** — 一套面向企业公开文本的分析技能包。
> 给它一份公告、财报或危机声明，它推演各方会怎么反应；给它一个事件，它反推该怎么说、能承诺到哪一步。

适配：Claude Code、Codex、WorkBuddy、豆包，以及其他能加载 Markdown 指令文件的 Agent。

---

## 这个技能包做什么

输入一份企业公文——上市公司公告、定期报告、澄清公告、问询回复、危机声明、道歉信、公关稿、内部信、ESG 报告——输出一份分层推演：这份文本说了什么，各方会在意什么、底线在哪、可能怎么反应，以及接下来该盯哪些信号。

具体做五件事：

- **拆结构**：定文种、套骨架，找出「本该有却没有」的组件——缺件本身就是信号。
- **建底座**：把时间线、主体、既往记录、同业对照查清，每条事实附来源与可信度等级；查不到就写「未查到」，不拿推测填。
- **推演人**：9 类利益相关者（公众、监管、资本、客户、员工、供应商与渠道、媒体、社区、竞争对手），按权力／合法性／紧迫性排优先级，给出触发条件、方向、强度、时点，并判断会不会结盟放大。
- **标话术与数字**：逐句标注声明用了哪种策略、前后是否自洽；财报类再叠一层科目与披露信号，对照措辞的实务读法。
- **给结论**：最坏结果、可核验的承诺、观察指标。长周期事件可以立项，按期回填事实再复检。

反向也成立：只给一个事件、没有公文时，走发布侧，产出承诺边界三分（可承诺／不可承诺／需上报）、口径草案与发布前审批提示。

用法分四档：**速读**（一页内说清这份公文讲了什么）、**标准分析**（完整报告 + 独立复核，默认）、**跟踪复检**（与上期对比）、**口径研判**（发布侧）。

系统有 2 个 Agent 和 9 个技能协作完成这些任务；判据放在知识库里按需读取，不整包塞进上下文。

## 怎么使用

纯 Markdown 与 YAML，没有运行环境要求，也不需要安装依赖。把整套目录放进 Agent 能读到的位置即可。

### 路线 A：把仓库交给 Agent（推荐）

> `https://github.com/7ropak/gongwen-analysis-skill`

Agent 会自行解析仓库，入口是 `agents/公文分析Agent.md`。

### 路线 B：取到本地再接入

```
git clone https://github.com/7ropak/gongwen-analysis-skill.git
```

然后把这句话交给你的 Agent：读取 `gongwen-analysis-skill/agents/公文分析Agent.md`，按其中的入口协议执行。

调用时只需要说清三件事：

```
调用 公文分析Agent：
 公文内容：[粘贴原文 / 链接 / 文件]
 主体：某公司（可省）
 模式：标准
```

发布侧换成 `事件描述：……` 与 `模式：口径研判`。时间窗、上市地、关注群体等可选字段见 `schemas/分析输入.schema.yaml`。

## 目录里有什么

- `agents/` —— 2 个 Agent：`公文分析Agent.md` 是主入口，负责编排；`分析审计Agent.md` 在独立上下文里做复核。
- `skills/` —— 9 个技能，一段一件：类型与结构解析、事件背景调研、利益相关者建模、声明语用标注、财务与合规信号扫描、分析报告生成、跟踪立项管理、口径研判与生成、词库维护。
- `schemas/` —— 5 份 YAML 契约：分析输入、分析输出、口径研判、跟踪立项、经验配置。字段与章节顺序以契约为准。
- `knowledge-base/` —— 判据库：公文类型库、利益相关者基线、声明策略库、公关危机响应流程、信号库、潜台词库，以及词库三卷（表态程度谱系、企业声明用词、模糊与限定用词）和用户经验。
- `prompts/` —— 可复用的口径片段与输出模板，只放被 Agent 和技能引用的内容。
- `docs/` —— 信息架构：目录职责与产物存放规则。

运行时还会生成 `output/`（交付版报告）、`debug/`（过程记录）、`data/`（调研原始记录与跟踪立项），这三个目录随仓库分发时不包含。

能不能改：除 `schemas/` 外基本都是纯文本。改词条、加群体、换模板、调口径，直接编辑对应文件；改契约则要同步改引用它的技能。

## 它怎么工作

一份公文进来，先定文种与法定性——强制披露、自律要求、自愿披露、无强制，四档决定后面哪些方法能作主判据、哪些只能辅助；这一步判错，后面的语用分析会整体偏。接着建事实底座：时间线、主体、既往、同业，每条带来源。然后把人放进局内，按优先级排序，看谁会先动、会不会结盟放大。文本层逐句标注表态与限定，财务类再叠科目与披露信号。最后归结到结论层：最坏结果、可核验的承诺、该盯的时点；要长期看的转成立项，按期回填事实再复检。

解读侧与发布侧方向相反，但共用同一套群体基线与策略编号——所以「别人会怎么读」和「我该怎么写」能对得上。

## 关键设计

- **双层产物**——交付版只放结果，调试件放判据与核对记录。最终读者要的是「说了什么、会怎样」，方法痕迹一多，推断就容易被当成结论；需要复查的人另有完整过程可看。
- **词库是判据，不是词典**——「遗憾」和「道歉」差一档，这一档决定对方下一步动作。把分寸差写成可比对的条目，分析才不靠语感。
- **契约先行**——输入、输出、跟踪、经验、口径五份 schema 定义字段，章节顺序与命名只认契约，同一类报告不会每次长得不一样。
- **双视角共用一套判据**——两侧方向相反，但引用同一份群体基线与声明策略编号，写出来的口径才能经得起自己那套推演。
- **复核独立于分析**——复核者先读原文自行判断，再比对结论，且不读分析者的中间推理；共用上下文会继承同一个误读。
- **概率只给档，不给百分比**——没有校准样本时，精确数字只是虚假的确定感；档位加上观察指标，才是可验证的。

## 边界与不做什么

- **不构成投资建议**：不给评级、目标价、估值，也不做交易时点判断。
- **不构成法律意见**：涉诉涉监管的判断只写到「需核实项 + 核实路径」，不做法律定性。
- 只用你提供的文本与公开信息，不检索非公开材料。
- 潜台词清单与量化阈值是**经验口径**，不是监管规则，不能当合规依据使用。
- 没有校准样本时，推演结论标注为未校准，可靠性低于事实层；请结合一手材料使用。
- 发布侧产物是**内部研判辅助**，不是可直接对外的成品稿；不生成虚假陈述、不规避法定披露义务、不代填内部证据。
