# 事件背景调研

> 定位：流水线 **S2**——建立「事实底座」：事件脉络、主体画像、既往表现、同业对照。
> 调用方：`公文分析Agent` ｜ 配套：信源三标签口径（`prompts/分析口径片段.md` 片段 C）

---

## 输入

| 字段 | 必填 | 说明 |
|---|---|---|
| 主体 | 条件必填 | 发布主体；未给时由 S1 的「事件线索／发布主体」推断并标注「推断」 |
| 事件 | 条件必填 | 事件名或一句话描述；未给时取自 S1 输出的「事件线索」；两者皆无 ⇒ 只做主体画像与公开记录检索，并在输出 `gaps` 登记「事件未明」 |
| 时间窗 | ❌ | 默认近 12 个月 |
| 关注群体 | ❌ | 指定时优先补该群体关心的信息 |

## 输出（事实底座）

```yaml
subject: { name, 性质, 规模, 上市地, 实控人/大股东 }
timeline:
  - { date, event, source_url, source_level }
prior_record:
  - { 类型: 既往危机/处罚/诉讼/承诺未兑现, date, 摘要, source_url }
industry_peer:
  - { 同业对照事实, source_url }
gaps:
  - { 想查而未查到的信息, 尝试过的检索路径 }
```

---

## 执行步骤

1. **拆检索问题**：把「了解事件背景」拆成 4–6 个可检索问题（何时发生／谁卷入／进展／既往类似事件／同业对照／监管动向）。
2. **分级检索**：官方一手（公告、监管文件、法院文书）→ 权威媒体 → 一般媒体。同一事实保留最高等级来源。
3. **建时间线**：按日期排序，每条附 `source_url` ＋ 等级。
4. **主体画像**：性质、规模、上市地、股权结构（可用公开工商／披露信息）。
5. **既往记录**：**尤为关键**——有无旧危机、被处罚、承诺未兑现、诉讼。理由：既往危机会改变本次文本的解读阈值（Coombs 的 Velcro effect），`声明策略库` §二 已引用该机制。
6. **同业对照**：同一事件是否在业内普遍存在（区分**竞争效应**与**传染效应**）。
7. **缺口登记**：查不到的写进 `gaps`，附尝试过的路径——不编造、不用推测填空。

---

## Guardrail

- **只检索公开信息**；不检索非公开材料，不猜测未披露事实。
- 每条事实必须可回溯到 URL／文号；转述媒体说法时注明「据 XX 报道」。
- 时间线中**未确认日期**写「约／不晚于」，不伪造精确日期。
- 冲突信息**并列保留**（两种说法 ＋ 各自来源），不擅自取舍。
- 检索失败或结果稀少时如实说明，并降低后续推演的置信档。
