# 利益相关者建模

> 定位：流水线 **S3（建模）＋ S6（反应推演）**——回答「谁在局内 → 谁最重要 → 会怎么动 → 可能扩散到哪」。
> 调用方：`公文分析Agent` ｜ 判据来源：`knowledge-base/利益相关者基线.md`

---

## 输入

| 字段 | 必填 | 说明 |
|---|---|---|
| 事件与主体 | ✅ | 来自 S2 事实底座 |
| 公文文本判断 | ✅ | 来自 S1（类型、缺失组件）＋ S4（主策略） |
| 用户关注群体 | ❌ | 有则置顶详述 |

## 输出

> **去向**：P／L／U 打分、档位名与 9 类逐项核对属**过程内容**，只进调试件；**交付版只取结果**——「谁在意什么、可能怎么反应、强度与时点」（判据 → `prompts/分析口径片段.md` 片段 H）。

| 字段 | 说明 |
|---|---|
| 群体表 | **内部**逐类核对 9 类；报告**只展示与事件实质相关者**（排除项留内部核对记录，供复核查） |
| salience 打分 | 每群体 P／L／U 三属性有无 → 档位（Definitive／Dominant／Dependent／Dangerous／单属性） |
| 交叉矩阵 | 身份重叠的组合（如员工＝股东） |
| 扩散路径 | 结盟路径 ＋ 级联风险 ＋ 行业传染判断 |
| 反应四元组 | 触发条件／反应方向／强度档／时点 |

---

## 执行步骤

### 第一段：建模（S3）

1. **列群体**：以 `利益相关者基线.md` §一 的 9 类为**检查表**（不是自由发挥）——逐类给出「在本事件中的具体所指」（如「监管」落到具体局／交易所部门）。**逐类核对在内部完成；报告中只展示与事件实质相关者**（排除项不列，理由留内部记录供复核查）。
2. **salience 打分**：每类逐项判 P／L／U 有无 ＋ **一句判据**（不能只给结论）。
   - 合计三属性 ⇒ Definitive；两属性 ⇒ 高；一属性 ⇒ 低；零属性 ⇒ **排除并写明理由**。
3. **建交叉矩阵**：找身份重叠（同一主体多重身份 ⇒ 影响面按并集计）。
4. **画扩散路径**：
   - 结盟路径：哪两个群体可合作补齐 salience 属性（如员工＋工会补权力）；
   - 级联风险：**首发反应方**与**高地位主体**（头部媒体、行业协会、政客）是否具备点火条件；
   - 行业传染：判断本次更可能走**竞争效应**（同业受益）还是**传染效应**（同业连带受损）。
   - **噪声过滤**：仅当某诉求在**一个群体内形成共性**时计入扩散；个例不计。

### 第二段：反应推演（S6）

5. 对每个 Definitive／两属性档群体，填**四元组**：
   - 触发条件（文本中的哪句／哪个缺失组件会点燃）；
   - 反应方向（接受／观望／施压／对抗）；
   - 强度档（低：个别发声｜中：群体性表态｜高：集体行动或动用权力）；
   - 时点（即时 24h／短期 1 周／中期 1 季／长期）。
6. **按强度倒序输出**，只详述前二至三档群体；其余列表带过（防输出膨胀）。

### 第三段：内部职能对照（可选，供发布侧与双向分析）

第 5 步之后，把**外部群体**与**发布方内部的研判分支**对上一次（对照表见 `knowledge-base/公关危机响应流程.md` §二）：

| 外部群体 | 对应内部分支 | 用途 |
|---|---|---|
| 公众／媒体 | 品牌／公关 | 解读侧推演 vs 发布侧叙事设计 |
| 客户／供应商渠道 | 客服／销售 | 解读侧推演 vs 实测反馈——**差异处标注**（差异即预警） |
| 资本 | 投资者关系 | 同上 |
| 监管 | 法务／合规／监管事务 | 承诺边界由该分支界定（见技能 `口径研判与生成` 步骤4） |
| 员工／社区团体／竞争对手 | 研发／产品工程 · 质量／制造／供应链（间接） | 事实底座的内部来源观察 |

> **触发判据**：用户要求「评估这份公文写得行不行」或走口径研判／双向模式时执行；纯解读任务可省略（写「未执行」）。

## Guardrail

- **概率只给档，不给百分比**（未校准前不写伪精度）。
- **逐类核对在内部完成**；报告只展示与事件实质相关的群体（排除项留核对记录，供复核查）。
- salience 是**快照**，须注明「随事件推进会变化」及变化触发条件。
- **危机回应类文本的时序**：辟谣／澄清／道歉类文本是「**危机在前、声明在后**」——须区分「声明发布前的既有反应」（归事实底座）与「声明发布后的增量反应」（归推演）。不得把已发生的事写成将要发生的事。
- 不作道德评价，只做后果推演。
- 用户经验区**已激活**且与知识基线冲突时并列呈现（`prompts/分析口径片段.md` 片段 E）；未激活时不读、不提示。

## 自检

- [ ] 是否检查了身份重叠？
- [ ] 扩散是否用了「结盟 ＋ 级联 ＋ 传染」三机制，而非单一判据？
- [ ] 反应是否给出四元组且概率只给档？
- [ ] 发布侧／双向模式下是否执行了内部职能对照段？
