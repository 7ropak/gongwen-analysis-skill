# 声明语用标注

> 定位：流水线 **S4**——回答「这份文本在做什么」：逐句标注修辞策略，再查一致性。
> 调用方：`公文分析Agent` ｜ 判据来源：`knowledge-base/声明策略库.md` · 词库（`knowledge-base/词库/`，用于定表态词的分寸与档位）
> 公共口径：**分层书写**（片段 A） · **来源等级**（片段 C） · **越界约束**（片段 D）——见 `prompts/分析口径片段.md`
> **适用范围（硬）**：**自愿披露类文本**（危机声明、道歉信、内部信、社媒声明）作**主判据**；法定公告仅作**辅助观察**（法定性四档定义 → `knowledge-base/公文类型库.md` §一）。

---

## 输入

| 字段 | 必填 | 说明 |
|---|---|---|
| 公文原文 | ✅ | 分句后的文本 |
| 法定性档 | ✅ | 来自 S1（决定本技能是主判据还是辅助） |
| 既往危机史 | ❌ | 来自 S2（影响危机簇判定） |

## 输出

> **去向**：框架编号（IRT／SCCT）与标注表属**过程内容**，只进调试件；**交付版只取结论**——用平实语言说明「这份文本在做什么」（如「只作否认与谴责」），不出现策略编号与姿态名（判据 → `prompts/分析口径片段.md` 片段 H）。

| 字段 | 说明 |
|---|---|
| 危机锚点 | 有无明确「被指控的行为」；无则标注「无危机锚点」并转常规解读 |
| 逐句标注表 | 位置／原文／策略编号／子策略名／判据 |
| 主策略 | 出现频次最高且处于关键位置者 |
| SCCT 姿态与危机簇 | deny／diminish／rebuild／bolster ＋ victim／accidental／preventable |
| 一致性结论 | 是否违反混用规则（**重点报警项**） |
| 归因偏差 | 好消息内归因次数／坏消息外归因次数 |
| 可疑处清单 | 标注突兀、段落错位、承诺空转之处 |

---

## 执行步骤

1. **分句编号**：按自然段＋句序编号（如 P2-3），便于审计比对。
2. **定位危机锚点**：找出「被指控／被质疑的行为」与「被归因负责的主体」。若无 ⇒ 结束语用分析，转「常规解读」（结构＋事实为主）。
3. **逐句打标**：对照 `声明策略库.md` §一 的 14 子策略。判据＝**文本特征**（如「占比极小」⇒ #8 淡化伤害）。一句可多标，但须给判据。
   - **遇表态词先查词库**：拿不准分寸时读 `knowledge-base/词库/企业声明用词.md`（按「表态档位」与「行动档位」两轴定位），不凭语感判断强弱。**表态档位与行动档位须分开记**——「强烈谴责」属表态高分，不代表行动强。
   - **14 子策略无对应项时**：标为「框架外 · <类别>」并指向词库，不硬套编号（见 §4.2 框架缺口）。
4. **判危机簇与姿态**：按 Coombs 三簇（victim／accidental／preventable）＋ 10 策略归入 4 姿态。
   - **放大器**：有负面前史时，标注「Velcro effect 风险」。
5. **查一致性**（硬规则）：
   - `deny` 与 `diminish`／`rebuild` 混用 ⇒ **违规**；
   - `diminish` ＋ `rebuild` 叠加 ⇒ 合规；
   - `victimage` 用于非 victim 簇 ⇒ 视为推责。
   > 一致性违规是「显得虚伪」的主要机制，**比策略选择本身更值得报警**。
6. **算归因偏差**：统计好消息内归因／坏消息外归因各几次，给出方向判断。
7. **列可疑处**：与 S1 的缺失组件互参（如「只有道歉、无措施时间表」⇒ 承诺空转）。

---

## Guardrail

- 标注意见**必须附原文逐字引述**；无引述的标注视为无效。
- 法定公告不得以语用标注作主判据（**理论移植风险**：法定文本修辞空间小）。
- 「甩锅」不等于失败——判据是**责任归因是否被公众接受**、**策略是否自相矛盾**，不直接判负。
- 不评价主体动机，只描述文本动作。
